# TypeSafeによる物語候補の整列

毎朝の締切で、既存の決定論的ロジックが安全に選んだ最大3件をTypeSafeへ送り、直近4件の出来事・現在地・章・獲得タグから最も自然につながる候補を先頭へ移す。連続依頼の候補には依頼名、全話数、現在の話数、目的を付け、未解決の続編を単発事件より優先させる。候補集合、出現条件、投票、報酬、戦闘結果はTypeSafeに変更させない。全プレイヤーで同じ並びを共有し、1人ごとの画面表示では呼び出さないため、200人が遊んでもAPI回数は基本的に世界ごとに1日1回。

TypeSafeのChoiceを使用し、`jev-latest`へ構造化したゲーム状態と候補IDを渡す。確信度0.35未満、候補外の回答、2.5秒のタイムアウト、HTTPエラー、APIキー未設定では、従来の順番をそのまま使う。日本語は英語より精度が低いという現行モデルの制約があるため、判断指示は英語にし、低リスクな並べ替えだけを任せる。

Jevが選んだ先頭候補と、実際にJevの判断が採用されたかは日ごとにD1へ保存する。今日画面は直近3件を「あらすじ」として並べ、連続依頼なら「第2話 / 全4話」と次の目的を表示する。Jevは文章を生成せず、本筋の選択を担当する。本文は検証済みのイベント文章を時系列につなぐ。

APIキーはブラウザやリポジトリに置かず、Cloudflare WorkerのSecret `TYPESAFE_API_KEY` に保存する。ローカルは環境変数またはWranglerのローカルSecretで設定する。キーを設定しなくてもゲーム全体とテストは動作する。

本番設定例：Workerディレクトリで `wrangler secret put TYPESAFE_API_KEY` を実行し、通常の `pnpm run release` で反映する。秘密値をログへ出さない。

## Jev 作戦参謀

戦闘準備画面の「Jevに作戦を考えてもらう」は、敵の能力・行動表と、参加中の仲間の能力・装備中の技を `jev-latest` へ送り、各人8ターンの行動候補をChoiceで受け取る。提案は戦闘を自動実行せず、通常の技選択表へ入るため、プレイヤーが確認・修正してから挑戦できる。

サーバは回答が装備中の技または待機であることを検査する。確信度0.25未満、候補外の技、5秒のタイムアウト、HTTPエラー、APIキー未設定では、そのマスまたは作戦全体を基本作戦へ戻す。APIキーは物語候補の整列と同じWorker Secretを使い、ブラウザへ渡さない。

同じプレイヤー・同じ戦闘日・同じ敵とパーティ構成への成功した提案はD1へ保存する。再度ボタンを押してもJevを呼び直さず、装備や能力が変わって入力の指紋が変わったときだけ新しい提案を取得する。

## Jev 育成相談

酒場では現在のパーティ構成、候補者の職業・レベル・素質・費用、プレイヤーの所持金から1人を推薦する。雇用は自動実行せず、候補者カードへ推薦印を付けるだけにする。

装備画面では選択中の仲間について、職業・素質・習得済みの技とパッシブ・現在使える所持装備をJevへ渡す。他の仲間が使用中で余りがない装備は候補から除外する。返答は所持・習得済みのIDだけに検証し、アクティブ6枠・パッシブ2枠の上限へ収める。武器・防具とスキルは別々の確認ボタンで適用する。

成功した推薦は、プレイヤーと入力状態の指紋ごとにD1へ保存する。パーティ、所持金、所持品、習得状態が変わらない限りTypeSafeを再呼び出ししない。障害・低信頼・キー未設定では、酒場は素質順、装備は現在の構成へ戻す。
