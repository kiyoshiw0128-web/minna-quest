# 段階3d — 転職・装備枠・パーティ操作

## 1. なぜこれを先にやるか

**いま9職業のうち8つに手が届かない。** 主人公は戦士固定で作られ、転職する手段が
どこにも無い。技も42個あるが、大半は他の職業の習得表にあるので覚えられない。
上級職の解禁条件（戦士Lv20＋僧侶Lv15など）も、僧侶になれないので満たせない。

装備枠も同じ。アクティブ6枠・パッシブ2枠という「枠の取り合いが編成の面白さ」
（全体設計 §4.2）が、枠をいじれないため存在しない。

全体設計が柱として挙げている「職業を変えて上級職」が、まるごと動いていない。

## 2. 範囲

- 転職
- 装備枠（アクティブ・パッシブ）の変更
- パーティの並べ替えと解雇
- 上の3つを操作する画面

**やらないもの:** ペット、装備品（武器・防具）、第2章以降のボス。

## 3. 転職

`POST /api/job` — `{ characterId, jobId }`。

判定は core の `canChangeJob` / `changeJob` に任せる。**サーバで条件を書き直さない。**
書き直すとエンジンと二重定義になり、必ずずれる。

- **金貨はかからない。** 全体設計 §4.1 が「いつでも気軽に職業を試せる」ことを
  転職の設計意図として挙げている。費用を取るとそれが消える
- 就いたことのある職業に戻る場合、その職業のジョブレベルは保たれている
- 転職した瞬間に、その職業のその時点のジョブレベルまでの技を習得する
  （core の `changeJob` がやる）
- **雇用メンバーも転職できる。** 主人公と同じ型なので特別扱いしない

`GET /api/me` に、各キャラの「就いたことのある職業とそのレベル」「いま就ける職業」を足す。
就ける職業が画面で分からないと、条件を満たしたことに誰も気づけない。

## 4. 装備枠

`POST /api/equip` — `{ characterId, activeIds, passiveIds }`。

判定は core の `equipActive` / `equipPassive` に任せる。

- 習得していない技は装備できない
- アクティブ6枠・パッシブ2枠を超えられない
- 重複は不可
- **両方を1回で受ける。** 片方ずつにすると、途中で失敗したとき
  「アクティブだけ変わった」状態が残る

## 5. パーティ操作

`POST /api/party` — `{ order: characterId[] }`。並びをそのまま受ける。

- 主人公を外せない（全体設計 §4.1 の「外せない1人目」）
- 自分のキャラだけを指定できる。他人のIDを混ぜたら断る
- 4人を超えられない

`POST /api/dismiss` — `{ characterId }`。雇用メンバーを解雇する。

- **金は戻らない**（全体設計 §4.4）
- 主人公は解雇できない
- **解雇したキャラの記録は消さない。** 消すと過去の戦闘の記録から
  参照できなくなる。パーティから外すだけにする

## 6. 画面

「仲間」の画面に足す。別タブにしない。

各キャラに対して。

- **転職**: 就ける職業の一覧から選ぶ。**就けない職業も条件つきで見せる**
  （「パラディン — 戦士Lv20・僧侶Lv15が必要」）。見えないと目標にならない
- **装備**: 習得済みの技から6枠・2枠を選ぶ。**技のMP・クールダウン・威力を出す**
- **並べ替え・解雇**

現在の職業のジョブレベルと、**次に何を覚えるか**を出す。
「あと2レベルで渾身の一撃」が見えると、育てる理由になる。

## 7. 触らないもの

- **`packages/core` を変更しない。** 必要な関数はすべてある
  （`canChangeJob` `changeJob` `equipActive` `equipPassive` `unlockedJobs` `learnsAt`）
- 既存APIの応答形を変えない（`GET /api/me` への追加は可）
- SQLは `apps/worker/src/store.ts` にだけ書く

## 8. テスト

1. 転職すると現在の職業が変わり、**冒険レベルが下がらない**
2. 就いたことのある職業に戻ると、**そのジョブレベルが保たれている**
3. 条件を満たさない上級職には転職できない
4. 転職した瞬間に、その職業のその時点までの技を習得している
5. 雇用メンバーも転職できる
6. 習得していない技は装備できない
7. 枠数を超えて装備できない
8. **装備の更新は片方だけ通らない**（アクティブが不正なら、パッシブも変わらない）
9. 主人公をパーティから外せない・解雇できない
10. 他人のキャラを操作できない（**認可の検査。必ず書く**）
11. 解雇しても、そのキャラの記録は残る

**8と10はガードを外すと落ちることを確かめること。**

## 9. 段階4c に送るもの

第2章以降のボス。第1章のボスは殴り合いになっており、
「溜めの窓に大技を集中させる」パズルは技が揃う第2章以降でないと成立しない。
