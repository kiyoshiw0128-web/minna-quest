# 段階11 — メールで合言葉を取り戻す

## 1. なぜ要るか

合言葉を無くすと**自力では戻れない**。保存しているのはハッシュだけで、復元できない。
実際に無くした人が出て、データベースを直接触って再発行した。
参加者が増えたら、その人は連絡してくるまで詰む。

## 2. 決めたこと

### 2.1 送るのは「1回だけ使える復旧コード」。合言葉そのものは送らない

**2026-09-06に方針を改めた。** 当初は「いまの合言葉をそのまま送る」としていたが、
それを実装すると、生きた認証情報をデータベースに平文で置くことになる。
`players.token_hash` は不可逆なので、後から送るには控えを持つしかない。
いまはハッシュしか無く、漏れても使えない。平文の控えを置いた瞬間、
メールを登録した人の分だけ「漏れたらそのまま乗っ取れる」状態になる。

作り直しを避けた理由（アドレスを知っている人が繰り返し要求して本人を締め出せる）
も、実際には弱かった。作り直しても本人には新しいものがメールで届くので、
締め出しではなく手間が増えるだけである。10分に1通の制限もある。
**恒久的な弱体化と釣り合わない。**

したがってこうする。

- 復旧の要求を受けたら、**使い捨ての復旧コード**を作ってメールで送る
- 保存するのは**そのハッシュと有効期限だけ**。平文はどこにも残らない
- コードが使われたときに初めて、**新しい合言葉を発行する**
- 有効期限は**30分**。使われたら即座に無効化する
- **要求しただけでは、いまの合言葉は無効にならない。** 締め出しは起きない

平文の認証情報をデータベースに置かない、という性質を保ったまま、
締め出しの心配も無くなる。

### 2.2 登録は任意

要らない人に必須にする理由がない。**参加の条件にしない。**

### 2.3 登録の有無で応答を変えない

「そのアドレスは登録されていません」と返すと、**誰が参加しているかを外から調べられる。**
登録済みでも未登録でも、同じ文面・同じ状態コードを返す。

### 2.4 同じ人へは一定時間に1通まで

そうしないと、アドレスを知っている人が受信箱を埋められる。**10分に1通**とする。
`players.recovery_sent_at` を見て、短ければ送らずに成功と同じ応答を返す
（送らなかったことも外から分からないようにする）。

## 3. データ

```
players  email TEXT                  ← 任意。未登録は NULL
         recovery_code_hash TEXT     ← 使い捨て復旧コードのハッシュ。平文は保存しない
         recovery_expires_at TEXT    ← その有効期限（30分）
         recovery_sent_at TEXT       ← 最後に送った時刻。連投を止めるため
```

**アドレスは平文で持つ。** 送信先として使うので、ハッシュにはできない。
個人情報が1つ増えることを承知の上で入れる。

## 4. API

`POST /api/email` — 認証あり。`{ email }` で登録・変更。空文字で削除。
**形式の検査は最低限にする。** 厳しくすると正当なアドレスを弾く。
`@` を含み空白が無い、程度で足りる。届くかどうかは送ってみるまで分からない。

`POST /api/recover` — **認証なし。** `{ email }`。
そのアドレスの登録があれば、使い捨ての復旧コードを作ってメールで送る。
無くても、あっても、同じ応答を返す。

`POST /api/recover/confirm` — **認証なし。** `{ code }`。
有効なコードなら、**新しい合言葉を発行して返す**。使ったコードは即座に無効化する。
期限切れ・使用済み・存在しないコードは、すべて同じ応答で断る
（どれに当たったかを外から区別させない）。

`GET /api/me` に、登録済みかどうかだけを足す（**アドレスそのものは返さない**。
端末を乗っ取られたときに、そこから連絡先まで抜けるのを避ける）。

## 5. 送信

`apps/worker/src/mail.ts`。**送信サービスのAPIを叩くだけの薄い層にする。**

- APIキーは Worker の秘密として持つ（`wrangler secret put RESEND_API_KEY`）
- **キーが設定されていない場合は、送らずに「送った」と同じ応答を返す。**
  キーを入れる前でも他の機能が壊れないようにする。
  ただしサーバのログには「キーが無いので送っていない」と残す。
  黙って成功したことにすると、届かない原因が分からなくなる
- 送信の失敗も応答には出さない（§2.3 と同じ理由）。ログには残す

## 6. 画面

「仲間」の合言葉の欄に、メールアドレスの登録を足す。

参加画面の「合言葉で戻る」に、「合言葉が分からない」から辿れる復旧の口を足す。
**送ったあとの文面に「登録されていれば送りました」と書く。**
「送りました」と断言すると、登録の有無が分かってしまう。

## 7. テスト

1. アドレスを登録・変更・削除できる
2. **他人のアドレスを変えられない**（認可）
3. 復旧の要求に対し、登録済みでも未登録でも同じ応答を返す
4. **10分以内の2度目は送らない**（ただし応答は同じ）
5. キーが未設定でも、応答は成功のまま。ログに残る
6. `GET /api/me` はアドレスそのものを返さない
7. 送る内容に復旧コードが含まれ、**合言葉そのものは含まれない**
8. コードを使うと新しい合言葉が発行され、**古い合言葉は使えなくなる**
9. **同じコードは二度使えない**
10. 期限切れのコードは使えない
11. **平文の合言葉も平文のコードもデータベースに残らない**

**2・3・4・6・9・11 はガードを外すと落ちることを確かめること。**

## 8. やらないこと

- パスワード、ログイン、アカウント統合
- メールの到達確認、開封追跡
- パスワードによるログイン（合言葉の仕組みのままにする）
